# Hướng dẫn kết nối QT Studio với máy GPU thuê (EZYCloudX hoặc nhà cung cấp khác)

QT Studio chỉ cần một Ollama HTTP API chuẩn. Tên nút trong cổng quản trị của nhà cung cấp có thể khác nhau; các bước dưới đây áp dụng cho máy Ubuntu/Windows có quyền quản trị.

## 1. Chuẩn bị máy GPU

1. Tạo máy có GPU và driver phù hợp; kiểm tra bằng `nvidia-smi` nếu dùng NVIDIA.
2. Cài Ollama theo tài liệu chính thức:
   - Ubuntu/Linux: `curl -fsSL https://ollama.com/install.sh | sh`
   - Windows: dùng OllamaSetup từ trang tải chính thức.
3. Tải đúng model mà Project sẽ dùng, ví dụ `ollama pull translategemma:12b`.
4. Kiểm tra `ollama list`, sau đó chạy `ollama ps` trong lúc thử model để xác nhận model thực sự dùng GPU.

Tài liệu chính thức: [Ollama trên Linux](https://docs.ollama.com/linux), [Ollama trên Windows](https://docs.ollama.com/windows), [`GET /api/tags`](https://docs.ollama.com/api/tags), [`POST /api/chat`](https://docs.ollama.com/api/chat).

## 2. Chọn đường mạng an toàn

Ưu tiên một trong hai phương án:

### A. VPN/private network

- Kết nối PC Windows và máy GPU bằng VPN riêng như WireGuard/Tailscale hoặc private network của nhà cung cấp.
- Cho Ollama lắng nghe trên interface private qua `OLLAMA_HOST`, rồi chỉ cho phép cổng 11434 từ IP VPN của PC.
- QT Studio chấp nhận HTTP khi URL dùng IP private, ví dụ `http://10.20.0.8:11434`.

### B. Reverse proxy HTTPS

- Giữ Ollama chỉ nghe localhost trên máy GPU.
- Đặt Caddy/Nginx/Apache phía trước, dùng domain và chứng chỉ TLS hợp lệ.
- Cấu hình reverse proxy chuyển `/api/tags` và `/api/chat` tới `http://127.0.0.1:11434`.
- Nếu cần token, reverse proxy phải kiểm tra header `Authorization: Bearer <token>`. Ollama gốc không tự tạo bearer token cho endpoint local.
- QT Studio dùng URL như `https://ollama.example.net` và token tương ứng.

Không mở công khai `http://0.0.0.0:11434` trên Internet. QT Studio chủ động từ chối HTTP tới hostname/IP công khai và không có tùy chọn bỏ qua chứng chỉ.

Theo FAQ Ollama, Linux systemd có thể đặt `Environment="OLLAMA_HOST=0.0.0.0:11434"` trong override rồi restart service; Windows nhận `OLLAMA_HOST` từ biến môi trường sau khi thoát và mở lại Ollama. Chỉ dùng `0.0.0.0` khi firewall/VPN/reverse proxy đã giới hạn truy cập.

## 3. Kiểm tra từ Windows trước khi mở QT Studio

Không có token:

```powershell
Invoke-RestMethod -Method Get -Uri 'https://ollama.example.net/api/tags'
```

Có bearer token:

```powershell
$headers = @{ Authorization = 'Bearer TOKEN_THU_NGHIEM' }
Invoke-RestMethod -Method Get -Uri 'https://ollama.example.net/api/tags' -Headers $headers
```

Kết quả phải có model đúng tên và `size` lớn hơn 0. Không dán token thật vào log, ảnh chụp hoặc ticket hỗ trợ.

## 4. Tạo profile trong QT Studio

1. Mở **Thiết lập dịch → AI & hiệu năng**.
2. Bấm **Profile mới**, chọn **Remote**.
3. Nhập tên dễ nhận biết, URL HTTPS hoặc IP private, token nếu reverse proxy yêu cầu.
4. Bấm **Làm mới model**. Chọn/nhập đúng tên model.
5. Bấm **Kiểm tra kết nối**.
6. Bấm **Lưu & sử dụng**, đọc cảnh báo gửi nội dung rồi xác nhận.
7. Kiểm tra status bar hiển thị `Remote · <tên profile> · <model>`.

## 5. Checklist thử một segment

### Local

- Chọn profile Local, làm mới model và kiểm tra kết nối.
- Mở Project synthetic, dịch một segment không chứa dữ liệu riêng.
- Xác nhận attempt được lưu đúng chapter/segment và status bar ghi Local.

### Remote

- Pause mọi queue đang chạy và chờ checkpoint hoàn tất.
- Chọn profile Remote, kiểm tra `/api/tags`, lưu và chấp nhận cảnh báo.
- Dịch một segment synthetic; xác nhận kết quả, metrics và status bar ghi Remote.
- Tắt mạng hoặc dừng Ollama, thử lại và xác nhận QT Studio báo lỗi remote mà không tự chuyển Local/provider khác.
- Mở lại QT Studio, xác nhận profile/model được khôi phục và token vẫn hiện qua PasswordBox; kiểm tra file Project không chứa token.

### Queue M4

- Tạo Queue Plan 2 chapter với Local hoặc Remote.
- Pause sau một checkpoint, đổi backend, rồi thử Resume job cũ.
- QT Studio phải chặn Resume và yêu cầu tạo Queue Plan mới; chapter đã hoàn tất không bị gửi lại.
