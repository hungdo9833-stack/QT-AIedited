# M6.5 — Local & Remote Ollama Backends

## Phạm vi

M6.5 cho phép QT Studio dùng Ollama trên máy Windows hiện tại hoặc một máy GPU từ xa. Cả hai đường đều đi qua `IOllamaClient`, `TranslationService` và coordinator M4 hiện có; không có translation engine, provider SDK hay cơ chế fallback thứ hai.

## Cấu hình người dùng

Trong **Thiết lập dịch → AI & hiệu năng**, người dùng có thể:

- chọn hoặc tạo profile Local/Remote;
- đặt tên profile, URL, bearer token tùy chọn và model;
- gọi `GET /api/tags` để làm mới danh sách model;
- kiểm tra kết nối và xác nhận model có dữ liệu thật trên server;
- lưu và kích hoạt profile mà không khởi động lại QT Studio.

Status bar luôn hiển thị loại backend, tên profile và model hiện hành. Local dùng cố định `http://127.0.0.1:11434/api/chat`. Remote nhận URL gốc, `/api` hoặc `/api/chat` và chuẩn hóa về `/api/chat`.

## Bảo mật

- Remote Internet chỉ nhận HTTPS với xác thực chứng chỉ mặc định của Windows. M6.5 không cài certificate callback và không bỏ qua lỗi TLS.
- HTTP chỉ nhận loopback hoặc địa chỉ IP private/link-local. Với máy thuê, nên dùng VPN/private network hoặc reverse proxy HTTPS có chứng chỉ hợp lệ.
- HTTP redirect bị tắt. Khi backend lỗi, request dừng tại backend đã chọn và không chuyển sang provider khác.
- Bearer token được lưu tại `%LOCALAPPDATA%\QTStudio\ollama-profiles.json` sau khi mã hóa bằng Windows DPAPI CurrentUser. Token không nằm trong `.qtproj`, chapter, translation history, backup/export hay Git.
- Trước lần đầu kích hoạt một đích Remote, ứng dụng nêu rõ prompt và nguyên văn segment sẽ rời máy rồi yêu cầu xác nhận. Thay URL của profile đã xác nhận sẽ yêu cầu xác nhận lại.
- `/api/tags` phải trả model có dữ liệu cục bộ trên server (`size > 0`) và không mang metadata `remote_host`/`remote_model`. QT Studio từ chối model cloud/forwarded trước khi gửi nguyên văn.

## Queue M4

Queue Plan chốt `ProfileId`, loại backend, endpoint và model. Token không nằm trong snapshot. Khi backend/model hiện hành khác snapshot, Start/Resume dừng trước request và yêu cầu tạo Queue Plan mới.

Ứng dụng không cho lưu/chuyển profile trong lúc một request hoặc coordinator đang chạy. Người dùng phải Pause và chờ checkpoint hoàn tất. Chapter đã commit, UserDraft, Approval, TranslationAttempt, history và progress được giữ nguyên. Job ở trạng thái Running khi crash vẫn mở lại thành Interrupted và không tự dịch; người dùng phải bấm Resume với đúng snapshot.

Job M4 cũ chưa có backend snapshot được hiểu là Local mặc định để giữ tương thích. Project cũ chưa có `OllamaProfileId` cũng mở bằng profile Local mặc định. Project tham chiếu profile đã bị mất sẽ báo lỗi và chờ người dùng chọn lại, không tự chuyển server.

## Persistence và schema

- `.qtproj` và chapter schema không đổi.
- `translation.json` có thêm `OllamaProfileId` tùy chọn; file cũ thiếu trường vẫn hợp lệ.
- Queue job schema vẫn là phiên bản 1; `Backend` là trường tùy chọn để đọc được checkpoint M4 cũ.
- Danh sách profile và secret nằm ngoài Project trong vùng dữ liệu người dùng Windows.

## Giới hạn và nghiệm thu thủ công

- Automated tests dùng fake HTTP; không cần GPU hoặc gửi nội dung thật.
- TLS sai được hệ thống Windows từ chối vì transport giữ certificate validator mặc định. Cần thử thêm với domain/chứng chỉ thật của server thuê.
- DPAPI cần Windows user profile được nạp. Test runner cô lập của Codex không có profile nên chỉ kiểm tra lỗi môi trường đã biết; package desktop cần được thử lưu/mở lại một token synthetic trên tài khoản Windows thực.
- Việc mở firewall, VPN, DNS, reverse proxy và cài model thuộc quản trị server, không do QT Studio tự thực hiện.
